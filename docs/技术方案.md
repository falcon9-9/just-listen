# JustListen 技术方案

> 当前范围：Bilibili Chrome 插件，覆盖 P0 字幕遮罩和 P1 无 CC 硬字幕识别。

## 1. 场景与方案

### 场景 A：用户不想一直盯着字幕

将 JustListen 直接挂载到当前播放器，而不是页面固定位置：

- 用书签条开启、关闭或按住临时显示字幕；
- 毛玻璃遮罩可拖动、缩放，参数只在代码配置中维护；
- 监听播放器替换和全屏变化，普通模式、网页全屏、浏览器全屏及番剧页面共用同一套挂载逻辑；
- 遮罩状态和位置保存到 `chrome.storage.local`。

### 场景 B：视频没有 CC，只有画面中的硬字幕

P1 不依赖遮罩是否开启，直接从原始视频画面识别字幕：

```text
当前视频帧 → 截取底部 35% → 语言注册表 → PaddleOCR → 字幕候选过滤
            → 连续两次命中确认 → Transcript（文字 + 时间戳）
```

实现约束：

- 只扫描视频画面底部，不采集播放器控制栏；
- 图片只存在于内存 Canvas，不保存字幕截图；
- 使用 PaddleOCR.js + PP-OCRv5，当前语言注册表顺序固定为中文 `zh` → 英文 `en` → 日文 `ja` → 韩文 `ko`；
- OCR 每 650ms 取样一次，相近文字连续命中两次才形成分句，降低单帧误识别；
- Transcript 当前只保存在面板内存中，刷新即清空；
- 根据已识别文字的 Unicode 字符分布判断字幕语言，不分析音频；
- 韩语等新语言先接入对应远程识别模型，再新增一个语言注册表入口，不修改 OCR 引擎和分句模块。

Language Registry 是 OCR 模型选择的唯一来源。数组位置就是尝试优先级：

```ts
[
  { language: 'zh', scripts: ['Han'], modelKey: 'pp-ocrv5-cjk' },
  { language: 'en', scripts: ['Latin'], modelKey: 'pp-ocrv5-cjk' },
  { language: 'ja', scripts: ['Kana', 'Han'], modelKey: 'pp-ocrv5-cjk' },
  { language: 'ko', scripts: ['Hangul'], modelKey: 'pp-ocrv5-ko', status: 'unavailable' },
]
```

| 配置项 | 作用 |
| --- | --- |
| `language` | 该入口对应的语言 |
| `scripts` | 可识别的文字系统或字符范围 |
| `modelKey` | 远程识别模型标识，可被多个入口复用 |
| `status` | 当前模型是否可用；不可用 entry 会被跳过并返回清晰原因 |

识别流程按注册表顺序尝试。某入口满足连续稳定、高置信度且字符匹配后立即停止，并在当前视频会话锁定。`zh`、`en`、`ja` 共享同一个 `modelKey` 时，通用加载器复用同一模型和同一帧推理结果，不因三个入口重复运行。中文和日文汉字存在歧义：日文优先依赖假名信号，纯汉字字幕需要多条字幕再确认，不用单帧结果直接锁定中文。新增韩语或其他语言时，只新增一个 registry entry，模型、引擎和分句逻辑不重写。

### 场景 C：视频有 CC 字幕

CC 与硬字幕 OCR 是独立字幕来源。当前只预留 CC Provider，不在硬字幕模块中混入站点字幕逻辑。后续两种来源输出统一的 Transcript Segment：

```ts
type TranscriptSegment = {
  id: string;
  start: number;
  end: number;
  text: string;
  confidence: number;
  samples: number;
};
```

本阶段只实现无 CC 场景的硬字幕 OCR；CC Provider 留到后续独立接入。

## 2. 模块边界

| 模块 | 职责 |
| --- | --- |
| Bilibili Adapter | 查找当前播放器，处理页面和全屏切换 |
| P0 Mask | 遮罩、书签条、Reveal 和偏好存储 |
| VideoFrameSource | 从视频底部取帧，仅返回内存 Canvas |
| OcrEngine | 加载模型、执行检测与识别、过滤字幕候选 |
| Language Registry | 维护有序识别入口和模型标识配置 |
| SegmentAssembler | 语言无关，按文字变化和连续命中生成时间段 |
| Language Detector | 根据已确认文字判断字幕语言 |
| CC Provider（预留） | 将站点 CC 转成统一 Transcript Segment |

各模块只通过视频元素或 Transcript Segment 连接，P0 遮罩、硬字幕 OCR 和 CC 可以独立启停。

## 3. 加载与体积

- 页面正常加载只注入约 214KB 的基础代码；
- 用户开始识别后才加载 OCR 运行模块；
- ONNX Runtime 固定使用 WASM-only 后端，不加载 JSEP/WebGPU 资源；
- 模型不打包进插件，按语言注册表首次使用时按需获取对应远程模型；
- 当前验证包约 36MB，主要来自 OpenCV 和 ONNX WASM，正式发布前再做运行时瘦身。

## 4. 当前边界

- 当前仅支持可被 Canvas 读取的视频；受跨域像素保护的视频无法 OCR；
- 当前只内置中、英、日识别入口；韩语等语言需要后续接入对应远程识别模型，但接入形式应只是新增注册表配置；
- 当前不持久化 Transcript，不保存图片，不上传视频帧；
- OCR 已通过实际硬字幕视频验证，下一步在统一 Transcript Segment 上实现点击跳转和单句循环。
