# 生活流语言学习 Extension — POC 需求文档

> 设计基线：`designs/justlisten-v2`（已确认）  
> 控制器形态：播放器右侧贴边「书签条」

## 1. 为什么做

### 产品定位

一个辅助**生活流语言学习**的 Chrome / Edge 浏览器插件。

用户不需要专门打开英语学习 App，也不需要寻找教材。

而是在自己原本就会进行的行为里：

> 追剧、看 vlog、看访谈、看 Bilibili 视频

通过几个非常轻量的交互，自然完成听力训练、重复输入和复述练习。

### 核心假设

很多人看带字幕的视频时，会下意识把注意力集中到字幕上。

结果是：

- 明明在“听英语”，实际上主要是在看字幕；
- 视线长期停留在画面底部，错过大量人物表情、动作和环境信息；
- 一旦关闭字幕，听力理解能力明显下降；
- 想重复听一句话时，需要频繁手动拖进度条，学习体验被打断。

因此，希望通过一个非常轻量的浏览器插件：

> **Hide → Listen → Repeat → Retell**

让用户在正常看视频的过程中，随时进入几秒钟的语言训练状态，然后马上继续看视频。

# 2. 给谁用

## 核心用户

经常在 Bilibili 看：

- 英美剧 / 海外影视
- Vlog
- 访谈
- YouTube 搬运视频
- 英语学习素材
- 其他外语视频

同时希望提高听力和口语的人。

第一阶段不限定英语。

遮字幕本身也可以用于：

- 普通话听力训练
- 粤语
- 日语
- 韩语
- 其他语言

因此产品底层定位可以是：

> **通过自己喜欢看的内容练语言。**

而不是传统意义上的“英语学习插件”。

---

# 3. 核心使用场景

## 场景 A：不想再盯着字幕看

用户正在 Bilibili 追剧。

视频本身已经烧录了中英双语字幕，无法通过播放器关闭。

用户发现自己的眼睛一直不自觉地看字幕。

于是：

1. 打开插件；
2. 开启「字幕遮罩」；
3. 拖动遮罩覆盖字幕区域；
4. 继续正常观看。

效果：

> 视线重新回到人物、动作和画面本身，同时被迫真正使用听力理解内容。

---

## 场景 B：一句话没听懂

用户看视频时遇到一句没听懂的话。

不希望：

> 暂停 → 拖进度条 → 找位置 → 播放 → 又拖回去

而是：

1. 点击 Transcript 中的这一句；
2. 视频自动跳转到对应位置；
3. 点击 Repeat；
4. 以 0.75× / 1× 等速度重复播放；
5. 听懂后继续观看。

---

## 场景 C：沉浸式复述

用户听到一句很喜欢或者很实用的表达。

例如：

> I didn't mean for this to happen.

用户：

1. 点击这一句；
2. 0.75× 播放；
3. Repeat 2～3 次；
4. 暂停；
5. 自己复述 / 模仿；
6. 继续看视频。

整个过程不需要离开视频页面。

核心体验：

> **看视频本身就是学习。**

---

# 4. 产品原则

### ① 不打断

插件应该服务于正常的视频消费，而不是把视频变成一堂课。

用户随时进入学习，又随时退出。

### ② 极简

不做大量学习功能。

POC 阶段只解决两个问题：

> **看不到字幕。**

以及：

> **一句话可以很容易地重复听。**

### ③ Content First

画面始终是主角。

插件 UI 不应该抢夺用户注意力。

### ④ Progressive Learning

学习动作应该非常轻：

> 看 → 没听懂 → Repeat → 看答案 → 继续

而不是要求用户进入一个完整学习流程。

---

# 5. 功能范围

# P0 — 字幕遮罩

这是 POC 最核心功能。

目标：

> **遮住视频中已经烧录进画面的字幕。**

即使 Bilibili 本身无法关闭字幕，也可以通过视觉遮罩让用户看不到。

## 5.1 开启字幕遮罩

插件在 Bilibili 视频播放器上覆盖一块可调整的区域。

播放器右侧贴边放置一枚竖向「书签条」控制器，上下两格无缝相接：

- 「别看字」：开启 / 关闭字幕遮罩；
- 「字幕列表」：打开 / 关闭 Transcript 面板。

书签条窄而安静，默认半隐，鼠标悬停时提亮；已开启的功能以高对比激活态表示。控制器形态在 POC 中固定，不向用户提供样式切换。

默认状态：

> Off

用户点击：

> Hide subtitles

出现遮罩。

---

## 5.2 毛玻璃效果

遮罩默认不是纯黑色矩形。

采用类似 Apple UI 的：

> **Frosted Glass / 毛玻璃**

视觉效果：

- 半透明；
- 背景模糊；
- 不显示清晰字幕文字；
- 不产生非常突兀的黑色区域。

目的：

让遮字幕成为一种自然的观看状态，而不是“屏幕下面出现一条黑条”。

实现约束：

- 模糊强度、遮罩浓度等毛玻璃参数作为代码内部配置项；
- POC 阶段不在页面、插件 popup 或设置面板中对用户外显；
- 参数需集中定义，便于后续根据测试反馈调整，不将其写死在多个样式或组件中。

---

## 5.3 拖动遮罩

用户可以直接拖动遮罩：

```text
┌──────────────────────────────┐
│                              │
│          VIDEO               │
│                              │
│                              │
│    ┌──────────────────┐      │
│    │   Frosted Glass  │ ← 可拖
│    └──────────────────┘      │
└──────────────────────────────┘
```

用户自己决定：

> 字幕在哪里。

POC **不做 AI 字幕识别**。

---

## 5.4 调整遮罩大小

用户可以改变：

- 宽度
- 高度
- 位置

满足：

- 单行字幕
- 双语字幕
- 字幕位置不同

等情况。

---

## 5.5 快速显示 / 隐藏

提供一个非常重要的交互：

> **Hold / Reveal subtitles**

用户没听懂时，可以临时看到原字幕。

例如：

```text
正常：

██████████████████


按住 Reveal：

I didn't mean for this to happen.
我不是故意让事情变成这样的。


松开：

██████████████████
```

理想状态下这是整个产品使用频率最高的操作之一。

用户不需要：

> 打开插件 → 关遮罩 → 看字幕 → 再打开遮罩。

而应该做到：

> **一键 Reveal。**

---

# P1 — Transcript + 单句循环

P1 开始解决第二个核心问题：

> **一句话重复听太麻烦。**

---

## 6.1 Transcript

播放器旁边提供 Transcript 面板。

例如：

```text
Transcript

00:31
I wasn't expecting this.

00:34
It's actually much bigger
than I imagined.

00:39
Let's go inside.
```

当前播放的句子自动高亮。

---

## 6.2 点击句子跳转

点击：

> It's actually much bigger than I imagined.

播放器直接跳转到对应时间。

不需要用户手动拖动进度条。

---

## 6.3 Repeat Sentence

选中一句以后：

```text
↻ Repeat
```

播放器自动：

```text
开始时间
    ↓
播放
    ↓
结束时间
    ↓
返回开始时间
    ↓
再次播放
```

用户点击停止后恢复正常播放。

---

## 6.4 单句倍速

针对当前句单独设置：

```text
0.5×
0.75×
1×
1.25×
```

例如：

> 视频本身仍然保持 1×。

但 Repeat 当前句时：

> 自动使用 0.75×。

结束 Repeat 后：

> 恢复 1×。

---

## 6.5 Repeat 次数

简单提供：

```text
Repeat

1×
2×
3×
∞
```

默认建议：

> 3×

满足：

**听 → 再听 → 模仿 / 复述**

---

# 7. POC 暂时不做

为了防止产品快速膨胀，以下功能明确不进入第一阶段：

- ❌ AI 对话
- ❌ AI 老师
- ❌ AI 自动生成学习计划
- ❌ 用户系统
- ❌ 登录
- ❌ 云同步
- ❌ 单词本
- ❌ Anki
- ❌ 生词解释
- ❌ 学习数据统计
- ❌ 打卡
- ❌ 社区
- ❌ 视频推荐
- ❌ 自动字幕 OCR
- ❌ AI 自动寻找字幕位置
- ❌ AI 消除硬字幕
- ❌ 手机 App
- ❌ 控制器形态切换
- ❌ 面向用户的毛玻璃参数调节

POC 只回答一个问题：

> **“遮字幕 + 单句 Repeat”是否真的让用户更愿意通过自己喜欢的视频练听力？**

# 8. 页面结构

尽量不做传统浏览器 Extension 的复杂 popup。

主要交互直接发生在 Bilibili 页面。

```text
┌──────────────────────────────────────────────┐
│                                           ┌────┐ │
│                  VIDEO                    │别看字│ │
│                                           ├────┤ │ ← 右侧贴边书签条
│          ┌──────────────────────┐           │列表│ │
│          │    Frosted Glass     │           └────┘ │
│          └──────────────────────┘                  │
│                                                │
└──────────────────────────────────────────────┘


                         ┌───────────────┐
                         │ Transcript    │
                         │               │
                         │ 00:31 ...     │
                         │               │
                         │ 00:34 ... ←   │
                         │               │
                         │ 00:39 ...     │
                         └───────────────┘
```

P0 甚至可以只有：

> **一个遮罩 + 一枚贴在播放器右缘的书签条。**

Transcript 到 P1 再增加。

# 9. UI / Visual Design

关键词：

> **Apple-like / Minimal / Calm / Invisible**

不是典型“英语学习软件”的：

- 大量黄色高亮；
- 卡片；
- 单词；
- 图标；
- 数据；
- 学习进度条。

而应该更像一个：

> **原本就属于播放器的功能。**

### UI 风格

- 大面积留白；
- 半透明材质；
- 毛玻璃；
- 轻微圆角；
- 极少按钮；
- 控制器采用右侧贴边的竖向书签条；
- 书签条两格无缝相接，默认半隐，悬停提亮，激活态清晰可辨；
- SF Symbols 风格图标；
- 克制的动画；
- 不外显毛玻璃参数等调试或复杂设置。

### 产品存在感

理想体验是：

> 用户打开以后很快忘记“自己正在使用一个插件”。

插件退到背景。

**内容始终在前。**

# 11. POC 成功标准

第一阶段不以：

- DAU
- 留存
- 收入
- 用户量

作为核心指标。

最先验证三个行为：

### ① 用户真的愿意遮字幕吗？

不是“觉得功能挺好”。

而是实际：

> 连续看 10～20 分钟视频仍然保持遮罩开启。

### ② Reveal 会被频繁使用吗？

如果：

> Hide → Listen → Reveal

成为自然行为，说明核心 interaction 成立。

### ③ 用户会不会主动 Repeat？

尤其观察：

> 用户遇到听不懂或者喜欢的表达时，会不会真的重复播放，而不是直接继续看。

如果这三个行为成立：

> **生活流学习这个假设值得继续。**

---

# 12. 产品核心

这个产品不是：

> **又一个英语学习工具。**

也不是：

> **一个功能很多的 Bilibili 插件。**

它想做的是：

> **在用户原本就在进行的生活中，插入极小的学习动作。**

核心循环：

**Watch**

↓

**Listen**

↓

**Reveal**

↓

**Repeat**

↓

**Retell**

↓

**Keep Watching**

让“学英语”和“看自己喜欢的东西”不再是两件不同的事情。
